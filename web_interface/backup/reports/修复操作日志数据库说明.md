# 修复操作日志数据库说明

## 问题描述

删除用户时出现错误：
```
null value in column "user_id" of relation "operation_logs" violates not-null constraint
```

这是因为数据库表 `operation_logs` 的 `user_id` 列仍然设置为 `NOT NULL`，但代码中已经将其设置为 `nullable=True`，并且外键约束需要支持 `SET NULL`。

## 解决方案

### 方法1：使用 Python 脚本（推荐）

如果您的应用使用 PostgreSQL 数据库，运行以下命令：

```bash
cd web_interface
python3 fix_operation_logs_user_id.py
```

脚本会自动：
1. 检测数据库类型
2. 修改 `user_id` 列为允许 NULL
3. 更新外键约束的删除规则为 `SET NULL`

### 方法2：使用 SQL 脚本（PostgreSQL）

如果您有直接访问 PostgreSQL 数据库的权限，可以运行：

```bash
# 设置数据库URL环境变量
export DATABASE_URL="postgresql://user:password@host:port/database"

# 运行修复脚本
./fix_operation_logs_postgresql.sh
```

或者直接使用 `psql` 执行以下 SQL：

```sql
-- 修改列，允许 NULL
ALTER TABLE operation_logs 
ALTER COLUMN user_id DROP NOT NULL;

-- 检查并更新外键约束
-- 首先删除旧的外键约束（如果存在）
ALTER TABLE operation_logs 
DROP CONSTRAINT IF EXISTS operation_logs_user_id_fkey;

-- 创建新的外键约束，使用 SET NULL
ALTER TABLE operation_logs 
ADD CONSTRAINT operation_logs_user_id_fkey 
FOREIGN KEY (user_id) 
REFERENCES users(id) 
ON DELETE SET NULL;
```

### 方法3：使用 SQLite（开发环境）

如果使用 SQLite 数据库，表结构应该已经支持 NULL（模型定义中已设置 `nullable=True`）。

如果仍然出现问题，可能需要重建数据库表。可以使用 Flask-Migrate 或手动重建：

```python
from app import create_app
from models.log import db, OperationLog

app = create_app()
with app.app_context():
    # 删除并重建表（注意：会丢失数据）
    OperationLog.__table__.drop(db.engine, checkfirst=True)
    OperationLog.__table__.create(db.engine, checkfirst=True)
```

## 验证修复

修复后，可以运行以下 Python 代码验证：

```python
from app import create_app
from models.log import OperationLog, db
from sqlalchemy import inspect

app = create_app()
with app.app_context():
    inspector = inspect(db.engine)
    columns = inspector.get_columns('operation_logs')
    for col in columns:
        if col['name'] == 'user_id':
            print(f"user_id column: nullable={col['nullable']}")
            break
```

应该显示 `nullable=True`。

## 注意事项

1. **备份数据**：在执行任何数据库修改操作前，请先备份数据库
2. **生产环境**：在生产环境中执行修复前，建议先在测试环境验证
3. **外键约束**：修复后，删除用户时，相关的操作日志的 `user_id` 会自动设置为 `NULL`，而不是删除日志记录，这样可以保留历史记录

## 代码修改说明

代码已经进行了以下修改：

1. **模型定义** (`models/log.py`)：
   - 外键约束已明确指定 `ondelete='SET NULL'`
   - `user_id` 列已设置为 `nullable=True`

2. **删除用户逻辑** (`routes/settings.py`)：
   - 在删除用户前，先尝试更新相关操作日志的 `user_id` 为 `NULL`
   - 如果更新失败（数据库表结构尚未更新），会记录警告但继续删除

3. **修复脚本**：
   - `fix_operation_logs_user_id.py`：Python 脚本，自动检测并修复
   - `fix_operation_logs_postgresql.sh`：PostgreSQL 专用 SQL 脚本

## 如果问题仍然存在

如果修复后问题仍然存在，请检查：

1. 数据库连接是否正确（环境变量 `DATABASE_URL`）
2. 是否有多个数据库（开发/生产环境）
3. 数据库用户是否有足够的权限执行 `ALTER TABLE` 操作
