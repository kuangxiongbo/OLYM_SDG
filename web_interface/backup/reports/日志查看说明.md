# 服务器日志查看说明

## 如何查看服务器日志

### 方法1：查看服务器终端输出（推荐）

如果服务器是在终端中启动的，直接查看该终端的输出即可。

**关键日志标识**：
- `[_load_template_data]` - 模板数据加载相关
- `[DataTransformer]` - 数据转换相关
- `[Step 6.5]` - 最终验证和修复
- `========== 日期列样本值 ==========` - 日期列的实际值

### 方法2：使用日志查看脚本

```bash
python3 查看服务器日志.py
```

这个脚本会显示：
- 最新失败任务的错误信息
- 任务配置信息
- 日期字段信息

### 方法3：使用日志监测脚本

```bash
# 监测指定进程
python3 monitor_logs.py <PID>

# 或监测另一个进程
python3 monitor_logs.py <另一个PID>
```

## 关键日志信息

### 1. 模板数据加载阶段

```
[_load_template_data] 加载模板 2 (话单模板)，字段数: 9
[_load_template_data] 发现模板中的sample_data，共 10 行，优先使用
[_load_template_data] 在sample_data中识别到日期列: ['call_time']
[DataValidator] ========== 修复日期列 call_time ==========
```

### 2. 数据字典验证阶段

```
[_load_template_data] 开始验证数据字典，字段数: X
[_load_template_data] 验证字段 call_time: 类型=<class 'list'>, 值示例=['2024-12-10', '2024-12-11', ...]
```

### 3. DataFrame创建阶段

```
[_load_template_data] DataFrame创建后，日期列 call_time 的样本值: ['2024-12-10', '2024-12-11', ...]
```

**如果看到以下日志，说明发现问题**：
```

[_load_template_data] ✅ 已修复日期列 call_time，重新构建为列表，长度: 100
```

### 4. 数据转换阶段

```
任务 {task_id}: [Step 6] 转换为SDGX格式...
[DataTransformer] ❌ 警告: prepare_for_sdgx发现列 call_time 第X行有被连接的日期: ...
[DataTransformer] ⚠️ 在prepare_for_sdgx中发现日期列 call_time 有问题，尝试修复...
```

### 5. 最终验证阶段

```
任务 {task_id}: [Step 6.5] 最终验证和修复日期列...
任务 {task_id}: [Step 6.5] 检查日期列 call_time...
任务 {task_id}: ❌ 发现第X行日期列call_time被连接: ...
任务 {task_id}: [Step 6.5] 开始修复日期列 call_time...
任务 {task_id}: ✅ 日期列 call_time 修复完成，所有值正常
任务 {task_id}: ========== 日期列样本值 ==========
任务 {task_id}: call_time: ['2024-12-10', '2024-12-11', ...]
```

## 如果看到错误

如果仍然看到日期字符串连接错误，请检查：

1. **是否有修复日志**：
   - 如果看到 `❌ 严重错误` 或 `⚠️ 警告`，说明修复逻辑已执行
   - 如果看到 `✅ 已修复`，说明修复已成功

2. **修复是否生效**：
   - 查看 `========== 日期列样本值 ==========` 的输出
   - 确认日期值是否正确（每个值应该是10个字符）

3. **如果修复没有生效**：
   - 检查是否有多个修复步骤
   - 检查是否有某个步骤覆盖了修复结果

## 下一步

如果问题仍然存在，请提供：
1. 完整的服务器日志（特别是 `[_load_template_data]`、`[DataTransformer]`、`[Step 6.5]` 部分）
2. `========== 日期列样本值 ==========` 的输出
3. 任何 `❌ 严重错误` 或 `⚠️ 警告` 的日志
