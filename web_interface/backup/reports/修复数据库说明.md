# 修复删除用户时的数据库错误

## 问题描述

删除用户时出现错误：
```
(psycopg2.errors.InFailedSqlTransaction) current transaction is aborted, commands ignored until end of transaction block
```

或者：
```
null value in column "user_id" of relation "operation_logs" violates not-null constraint
```

## 原因分析

1. **数据库表结构问题**：`operation_logs` 表的 `user_id` 列仍然设置为 `NOT NULL`
2. **外键约束问题**：外键约束的删除规则可能不是 `SET NULL`
3. **事务处理问题**：更新操作日志失败时，事务被中止但未正确处理

## 解决方案

### 步骤2：修复 PostgreSQL 数据库

如果使用的是 PostgreSQL，需要执行以下 SQL：

#### 方法1：使用修复脚本（推荐）

```bash

# 如果设置了 DATABASE_URL 环境变量，脚本会自动检测

```

#### 方法2：直接使用 psql

```bash
# 连接到 PostgreSQL 数据库
psql -h hostname -U username -d database_name

# 执行以下 SQL 命令
```

```sql
-- 1. 修改列，允许 NULL
ALTER TABLE operation_logs 
ALTER COLUMN user_id DROP NOT NULL;

-- 2. 检查并更新外键约束
-- 首先删除旧的外键约束（如果存在）
DO $$
DECLARE
    fk_constraint_name TEXT;
BEGIN
    SELECT constraint_name INTO fk_constraint_name
    FROM information_schema.table_constraints tc
    JOIN information_schema.key_column_usage kcu
    ON tc.constraint_name = kcu.constraint_name
    WHERE tc.table_name = 'operation_logs'
    AND kcu.column_name = 'user_id'
    AND tc.constraint_type = 'FOREIGN KEY'
    LIMIT 1;
    
    IF fk_constraint_name IS NOT NULL THEN
        EXECUTE 'ALTER TABLE operation_logs DROP CONSTRAINT ' || fk_constraint_name;
    END IF;
END $$;

-- 3. 创建新的外键约束，使用 SET NULL
ALTER TABLE operation_logs 
ADD CONSTRAINT operation_logs_user_id_fkey 
FOREIGN KEY (user_id) 
REFERENCES users(id) 
ON DELETE SET NULL;

-- 4. 验证修改结果
SELECT column_name, is_nullable, data_type 
FROM information_schema.columns 
WHERE table_name = 'operation_logs' AND column_name = 'user_id';

SELECT constraint_name, delete_rule
FROM information_schema.referential_constraints rc
JOIN information_schema.key_column_usage kcu
ON rc.constraint_name = kcu.constraint_name
WHERE kcu.table_name = 'operation_logs'
AND kcu.column_name = 'user_id'
AND kcu.referenced_table_name = 'users';
```

### 步骤3：修复 SQLite 数据库

如果使用的是 SQLite，表结构应该已经支持 NULL（模型定义中已设置 `nullable=True`）。

如果仍然出现问题，可能需要重建数据库表：

```python
from app import create_app
from models.log import db, OperationLog

app = create_app()
with app.app_context():
    # 注意：这会删除所有操作日志数据！
    OperationLog.__table__.drop(db.engine, checkfirst=True)
    OperationLog.__table__.create(db.engine, checkfirst=True)
```

## 代码已修复

删除用户的代码已经更新，现在会：

1. **先删除用户的任务**：在删除用户前，先删除该用户的所有任务
2. **更新操作日志**：将相关操作日志的 `user_id` 设置为 `NULL`（如果数据库支持）
3. **错误处理**：如果更新失败，会回滚事务并返回明确的错误信息

## 验证修复

修复后，可以尝试删除一个测试用户，确认功能正常。

如果仍然遇到问题，请检查：

1. 数据库连接是否正确
2. 数据库用户是否有足够的权限执行 `ALTER TABLE` 操作
3. 是否有其他外键约束阻止删除
