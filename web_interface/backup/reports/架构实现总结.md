# 合成数据生成服务架构实现总结

## 一、新架构概述

基于SDGX示例代码和当前业务流程，我们设计并实现了一个更稳定、更可靠的架构，确保生成数据的稳定性和数据质量。

## 二、核心设计原则

1. **最小化预处理**：只修复关键数据质量问题，不破坏原始数据
2. **充分利用SDGX能力**：使用SDGX的自动识别机制（`Metadata.from_dataloader()`）
3. **完全按照SDGX示例代码**：确保与SDGX标准流程一致
4. **数据质量保障**：在数据传递给SDGX之前，确保数据格式正确
5. **架构简洁**：减少模块间依赖，提高可维护性

## 三、新服务类

### 3.1 DataPreparationService（数据准备服务）

**文件**：`web_interface/services/data_preparation_service.py`

**职责**：
- 数据加载（文件/模板）
- **仅修复关键数据质量问题**（如日期时间连接）
- 最小化数据验证
- 保存原始数据副本

**关键方法**：
- `load_data()`: 加载数据（文件或模板），返回数据和原始数据副本
- `fix_critical_issues()`: 修复关键问题（日期时间连接、'NAN_VALUE'字符串）
- `validate_minimal()`: 最小化验证（数据不为空、最小行数）
- `get_source_file_path()`: 获取源文件路径（用于直接使用CsvConnector）

**修复策略**：
- ✅ 修复日期时间列被连接的问题（关键！）
- ✅ 清理'NAN_VALUE'字符串
- ❌ 不进行类型转换（让SDGX自动识别）
- ❌ 不修改数据内容（保持原始数据）

### 3.2 SDGXService（SDGX服务）

**文件**：`web_interface/services/sdgx_service.py`

**职责**：
- 封装SDGX的标准流程
- 完全按照SDGX示例代码实现
- 提供统一的接口

**关键方法**：
- `create_connector()`: 创建DataConnector（CsvConnector或DataFrameConnector）
- `create_metadata()`: 创建Metadata（使用`Metadata.from_dataloader()`自动识别）
- `create_synthesizer()`: 创建Synthesizer
- `train()`: 训练模型（`synthesizer.fit()`）
- `generate()`: 生成数据（`synthesizer.sample(count)`）

**实现原则**：
- 完全按照SDGX示例代码
- 不做任何额外的预处理
- 充分利用SDGX的自动识别能力

## 四、数据流程

```
用户上传文件/选择模板
    ↓
DataPreparationService.load_data()
    - 加载数据
    - 保存原始数据副本（用于后续保存）
    ↓
DataPreparationService.fix_critical_issues()
    - 修复日期时间连接问题（关键！）
    - 清理'NAN_VALUE'字符串
    ↓
DataPreparationService.validate_minimal()
    - 检查数据不为空
    - 检查最小行数
    ↓
SDGXService.create_connector()
    - 优先使用CsvConnector（如果是CSV文件）
    - 否则使用DataFrameConnector
    ↓
SDGXService.create_metadata()
    - 创建DataLoader
    - Metadata.from_dataloader()（SDGX自动识别）
    ↓
SDGXService.create_synthesizer()
    - 创建Synthesizer（metadata, model, data_connector）
    ↓
SDGXService.train()
    - synthesizer.fit()
    ↓
SDGXService.generate()
    - synthesizer.sample(count)
    ↓
保存结果（使用原始数据副本作为"原始数据"）
```

## 五、与SDGX示例代码的对比

### 5.1 SDGX示例代码
```python
# 1. 创建连接器
data_connector = CsvConnector(path=file_path)

# 2. 创建DataLoader
data_loader = DataLoader(data_connector)

# 3. 自动识别Metadata
metadata = Metadata.from_dataloader(data_loader)

# 4. 创建Synthesizer
synthesizer = Synthesizer(
    metadata=metadata,
    model=CTGANSynthesizerModel(epochs=128),
    data_connector=data_connector
)

# 5. 训练
synthesizer.fit()

# 6. 生成
synthetic_data = synthesizer.sample(1000)
```

### 5.2 我们的实现
```python
# 1. 数据准备（最小化）
prepared_data, original_data = data_prep_service.load_data(file_id)
prepared_data = data_prep_service.fix_critical_issues(prepared_data)  # 只修复关键问题
prepared_data = data_prep_service.validate_minimal(prepared_data)

# 2. 创建连接器（优先使用CsvConnector）
source = source_file_path or prepared_data
data_connector = sdgx_service.create_connector(source)

# 3. 自动识别Metadata（完全按照SDGX示例）
metadata = sdgx_service.create_metadata(data_connector)

# 4. 创建Synthesizer（完全按照SDGX示例）
synthesizer = sdgx_service.create_synthesizer(metadata, model, data_connector)

# 5. 训练（完全按照SDGX示例）
sdgx_service.train(synthesizer)

# 6. 生成（完全按照SDGX示例）
synthetic_data = sdgx_service.generate(synthesizer, count)
```

## 六、关键修复点

### 6.1 日期时间连接问题

**问题**：数据源中的日期时间值被连接成 `'2025/4/1 9:282025/4/1 9:59...'`

**解决方案**：
1. 在 `DataPreparationService.fix_critical_issues()` 中修复
2. 使用 `DataValidator.fix_date_value()` 提取第一个日期时间
3. 标准化为 `YYYY-MM-DD HH:MM:SS` 格式
4. 在传递给SDGX之前完成修复

### 6.2 字段类型识别

**问题**：手动识别字段类型，与SDGX自动识别不一致

**解决方案**：
1. **完全使用SDGX自动识别**：`Metadata.from_dataloader()`
2. 前端提供"自动识别"选项，默认全部自动识别
3. 如果用户手动配置类型，仅作为参考，SDGX仍使用自动识别

### 6.3 数据一致性

**问题**：原始数据、训练数据、生成数据可能不一致

**解决方案**：
1. 在加载数据时，立即保存原始数据副本
2. 所有预处理都在副本上进行
3. 保存结果时，使用原始数据副本作为"原始数据"

## 七、优势

1. **稳定性**：最小化预处理，减少出错可能
2. **准确性**：充分利用SDGX的自动识别能力
3. **简洁性**：架构清晰，易于维护
4. **一致性**：与SDGX示例代码保持一致
5. **可扩展性**：易于添加新功能
