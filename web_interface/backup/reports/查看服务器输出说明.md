# 如何查看服务器日志输出

## 问题说明

`monitor_logs.py` 脚本使用 macOS 的 `log stream` 命令来监测系统日志，但 Flask 应用的日志通常输出到**标准输出（stdout）**，而不是系统日志。因此，`log stream` 可能无法捕获到这些日志。

## 解决方案

### 方法1：直接查看启动服务器的终端窗口（推荐）

如果服务器是在终端中启动的：
1. 找到启动服务器的终端窗口
2. 直接查看该窗口的输出
3. 日志会实时显示在那里

### 方法2：重新启动服务器并重定向输出到文件

```bash
# 停止当前服务器（Ctrl+C 或 kill 进程）
kill 14757

# 重新启动并保存日志到文件
cd "/Users/kuangxb/Desktop/AI 生成数据 SDG /web_interface"
python3 app.py > server.log 2>&1 &

# 实时查看日志
tail -f server.log
```

### 方法3：使用 Python 直接查看进程输出（如果可能）

由于 macOS 的限制，直接查看运行中进程的标准输出比较困难。最好的方法是：

1. **找到启动服务器的终端窗口**
2. **或者重新启动服务器并重定向输出**

## 关键日志位置

当执行数据生成任务时，日志会包含以下关键信息：

### 1. 模板数据加载
```
[_load_template_data] 加载模板 2 (话单模板)，字段数: 9
[_load_template_data] 发现模板中的sample_data，共 10 行，优先使用
[_load_template_data] 在sample_data中识别到日期列: ['call_time']
```

### 2. DataFrame创建（关键）
```
[_load_template_data] 数据字典验证完成，所有字段都是列表类型
[_load_template_data] DataFrame创建后，日期列 call_time 的样本值: ['2024-12-10', '2024-12-11', ...]
```

如果看到以下日志，说明发现问题：
```
[_load_template_data] ❌ 严重错误: 在创建DataFrame之前，日期列 call_time 的第一个值是被连接的字符串: ...
[_load_template_data] ✅ 已修复日期列 call_time，重新构建为列表，长度: 100
```

### 3. 数据转换
```
任务 {task_id}: [Step 6] 转换为SDGX格式...
[DataTransformer] ❌ 警告: prepare_for_sdgx发现列 call_time 第X行有被连接的日期: ...
```

### 4. 最终验证（最关键）
```
任务 {task_id}: [Step 6.5] 最终验证和修复日期列...
任务 {task_id}: ========== 日期列样本值 ==========
任务 {task_id}: call_time: ['2024-12-10', '2024-12-11', ...]
```

## 建议

**最简单的方法**：找到启动服务器的终端窗口，直接查看那里的输出。所有日志都会实时显示在那里。
