# 合成数据生成服务架构设计（稳定版）

## 一、设计原则

### 1.1 核心原则
1. **最小化预处理**：只做必要的数据修复，不破坏原始数据
2. **充分利用SDGX能力**：使用SDGX的自动识别机制，减少手动配置
3. **数据质量保障**：在数据传递给SDGX之前，确保数据格式正确
4. **架构简洁**：减少模块间依赖，提高可维护性
5. **错误处理**：完善的错误处理和日志记录

### 1.2 SDGX标准流程（参考示例代码）
```python
# 1. 创建DataConnector
data_connector = CsvConnector(path=file_path)  # 或 DataFrameConnector(df=df)

# 2. 创建DataLoader
data_loader = DataLoader(data_connector)

# 3. 自动识别Metadata
metadata = Metadata.from_dataloader(data_loader)

# 4. 创建Synthesizer
synthesizer = Synthesizer(
    metadata=metadata,
    model=CTGANSynthesizerModel(epochs=128),
    data_connector=data_connector
)

# 5. 训练
synthesizer.fit()

# 6. 生成
synthetic_data = synthesizer.sample(1000)
```

## 二、当前架构问题分析

### 2.1 问题清单
1. **过度预处理**：Step 2-6.5 有太多预处理步骤，可能导致数据被修改
2. **日期时间连接问题**：数据源中的日期时间值被连接，需要修复
3. **类型识别不准确**：手动识别字段类型，与SDGX自动识别不一致
4. **架构复杂**：多个模块（DataLoader, DataValidator, DataTransformer, SDGXAdapter），逻辑分散
5. **数据一致性**：原始数据、训练数据、生成数据可能不一致

### 2.2 根本原因
- 试图在SDGX之前做太多数据转换
- 没有充分利用SDGX的自动识别能力
- 对数据源的质量假设不足（如日期时间被连接）

## 四、关键修复点

### 4.1 日期时间连接问题修复

**问题**：数据源中的日期时间值被连接成 `'2025/4/1 9:282025/4/1 9:59...'`

**解决方案**：
1. 在 `DataPreparationService.fix_critical_issues()` 中修复
2. 使用 `DataValidator.fix_date_value()` 提取第一个日期时间
3. 标准化为 `YYYY-MM-DD HH:MM:SS` 格式
4. 在传递给SDGX之前完成修复

### 4.2 字段类型识别

**问题**：手动识别字段类型，与SDGX自动识别不一致

**解决方案**：
1. **完全使用SDGX自动识别**：`Metadata.from_dataloader()`
2. 前端提供"自动识别"选项，默认全部自动识别
3. 如果用户手动配置类型，仅作为参考，SDGX仍使用自动识别

### 4.3 数据一致性

**问题**：原始数据、训练数据、生成数据可能不一致

**解决方案**：
1. 在加载数据时，立即保存原始数据副本
2. 所有预处理都在副本上进行
3. 保存结果时，使用原始数据副本作为"原始数据"

## 六、数据质量保障措施

### 6.1 数据修复策略

**只修复会导致SDGX失败的问题**：
1. ✅ 日期时间列被连接（会导致类型转换失败）
2. ✅ 'NAN_VALUE'字符串（会导致类型转换失败）
3. ❌ 类型转换（让SDGX自动识别）
4. ❌ 数据内容修改（保持原始数据）

### 6.2 验证策略

**最小化验证**：
1. ✅ 数据不为空
2. ✅ 最小行数（>=10）
3. ✅ 允许空列（SDGX支持）
4. ✅ 允许部分空值（SDGX支持）

### 6.3 错误处理

1. **数据加载失败**：返回明确的错误信息
2. **数据修复失败**：记录日志，尝试继续
3. **SDGX训练失败**：返回详细错误堆栈
