# 测试用例文档

## 1. 测试概述

### 1.1 测试目标
确保 AI 数据平台的功能完整性、稳定性和安全性，验证前后端接口的正确性，保证用户体验。

### 1.2 测试范围
- 用户认证与授权
- AI 仿真数据生成
- AI 数据质量评估
- AI 数据脱敏
- 任务管理
- 系统设置（管理员功能）
- 操作日志

### 1.3 测试环境
- **开发环境**: http://localhost:5000
- **测试数据库**: SQLite（测试用）
- **测试工具**: Postman / curl / pytest

## 2. 认证模块测试用例

### 2.1 用户注册

**用例 ID**: TC-AUTH-001

**测试步骤**:
1. 发送 POST 请求到 `/api/auth/register`
2. 请求体包含有效的邮箱、密码等信息

**测试数据**:
```json
{
  "email": "test@example.com",
  "password": "Test123456",
  "confirm_password": "Test123456",
  "phone": "13800138000"
}
```

**预期结果**:
- 状态码: 200
- 返回成功消息
- 数据库中创建用户记录（status=pending）
- 发送激活邮件

**异常测试**:
- TC-AUTH-001-1: 邮箱已存在 → 返回 400
- TC-AUTH-001-2: 密码不一致 → 返回 400
- TC-AUTH-001-3: 邮箱格式错误 → 返回 400

### 2.2 账号激活

**用例 ID**: TC-AUTH-002

**测试步骤**:
1. 先注册用户获取激活码
2. 发送 POST 请求到 `/api/auth/activate`
3. 使用正确的激活码

**测试数据**:
```json
{
  "email": "test@example.com",
  "activation_code": "ABC123"
}
```

**预期结果**:
- 状态码: 200
- 用户状态更新为 active
- 可以正常登录

**异常测试**:
- TC-AUTH-002-1: 激活码错误 → 返回 400
- TC-AUTH-002-2: 激活码过期 → 返回 400
- TC-AUTH-002-3: 用户不存在 → 返回 404

### 2.3 用户登录

**用例 ID**: TC-AUTH-003

**测试步骤**:
1. 发送 POST 请求到 `/api/auth/login`
2. 使用已激活的账号

## 12. 测试执行计划

### 12.1 测试阶段

1. **单元测试**: 开发阶段，覆盖所有函数和类
2. **集成测试**: 功能完成后，测试模块间交互
3. **系统测试**: 完整功能测试，覆盖所有用例
4. **验收测试**: 用户场景测试，验证需求满足度

### 12.2 测试优先级

- **P0**: 核心功能（登录、生成、评估、脱敏）
- **P1**: 重要功能（任务管理、系统设置）
- **P2**: 辅助功能（日志查询、数据导出）

### 12.3 测试报告

测试完成后需输出：
- 测试执行总结
- 缺陷统计报告
- 性能测试报告
- 测试覆盖率报告
